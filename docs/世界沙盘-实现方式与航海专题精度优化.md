# 世界沙盘：实现方式与航海专题精度优化

> 核对日期：2026-10-29。当前实现来自 `src/views/ocean-atmosphere-interaction`。
> 本文前半部分描述已经存在的代码，后半部分是航海专题的后续设计建议。局部精细地形、历史航线和船舶通行功能尚未实现。

## 1. 总体结构

当前沙盘采用 **经纬度展开的矩形海洋 + 矢量大陆轮廓 + 高程起伏网格 + 地表纹理**。海陆形状和高程来自资料，海洋波光与教学过程由 Three.js 动画表现。

它适合观察全球海陆格局、海温分布与大尺度海气过程。用于航海专题时，可以保留全球底图，再为关键海峡、运河和港湾增加局部精细模型。

需要分清三个概念：

- **轮廓精度**：两岸、岛屿、水道是否存在，形状与连通关系是否正确。
- **高程精度**：陆地起伏的采样间距与高程质量。
- **显示精度**：网格密度、贴图分辨率、抗锯齿和屏幕上的可见尺寸。

提高显示精度不会自动补出源资料已经省略的海峡，也不会增加高程资料的真实细节。

## 4. 经纬度怎样变成沙盘坐标

当前常量：

```ts
WORLD_WIDTH = 72
WORLD_DEPTH = 36
WORLD_LON_START = -30
WORLD_LON_END = 330
SEA_Y = 0
```

经度先循环归一到 `[-30°, 330°)`，再映射至 X 轴；纬度映射至 Z 轴，北方为负 Z：

```text
λ′ = wrap(经度, -30°, 330°)
x  = (λ′ - 150°) / 360° × 72
z  = -纬度 / 180° × 36
```

相当于经纬度线性展开的等距柱状式平面。中央经线为 150°E，切缝位于 30°W，因此太平洋成为主要观察区域，非洲可以整体位于左侧。

注意：

- Three.js 坐标是显示单位，不是米。不能用模型中的直线长度直接当航行距离。
- 高纬度与低纬度的东西向比例不同；未来航程统计应基于经纬度计算测地线分段长度。
- 切缝处会出现坐标跳变。大陆已做接缝裁切，未来航线仍需单独拆段，不能把屏幕左、右边缘直接连成一条穿越大陆的长线。当前对源数据原有 180° 接缝的处理依赖现有 GeoJSON 的切分方式；不能据此保证任意跨日界线多边形都能直接导入。
- `geoToWorld()` 返回的 Y 为 0；实际水面放在 Y=0.015，船舶吃水、尾迹等需使用实际水面高度。

## 5. 陆地如何生成

### 5.1 矢量预处理与陆地判定

`prepareCountries()` 读取 Polygon / MultiPolygon，保留外环和内环，并计算包围盒。`createLandMask()` 使用 10° 分桶缩小候选范围，再执行点在多边形内的判定。

这里使用的是国家面资料，既有真实海岸，也有国家之间的内部边界。航海专题制作局部陆地时，应将相邻国家面合并成连续陆地，水道开口依据水域资料确定。

### 5.2 第一层：大陆轮廓底面

每个面通过 `THREE.ShapeUtils.triangulateShape()` 三角化，内环作为孔洞保留。之后按 30°W 切缝裁开，再投影到沙盘两侧，避免三角形横跨整张地图。

生成的网格名为 `precise-land-silhouette`，普通陆地底面 Y=0.14。这里的“precise”仅指保留输入矢量的轮廓，不代表源资料具备局部航道级精度。

### 5.3 第二层：封闭侧壁

沿轮廓向下生成侧壁 `land-sea-sealed-sides`，下沿为 Y=-0.24，使大陆与海面交界有厚度。沙盘外边缘的侧壁下沿稍向内缩，避免与海洋长方体外表面共面闪烁。

侧壁使用独立颜色材质。地表影像中的蓝色海岸像素不会被拉到侧壁上，减少岛屿边缘出现蓝色立面的现象。

### 5.4 第三层：高程起伏

起伏网格以 `GRID_STEP = 1` 建立，即经纬度方向每 1° 一个采样节点。高程来自 2° 源格网的双线性插值，当前高度表达式为：

```ts
y = LAND_Y + RELIEF_CLEARANCE + meters / 3400
// LAND_Y = 0.14，RELIEF_CLEARANCE = 0.03
```

这是一种适合课堂观察的垂直夸张，不是水平、垂直使用相同比例的真实地形模型。1° 网格也没有将 2° 源数据变成更高精度的观测资料。

靠海的起伏节点会降低至 Y=0.17，接近轮廓底面。当前只在一个三角形的三个顶点均被判定为陆地时保留该三角形。

**这个筛选不是完整的海岸裁切。** 三个顶点都在陆地上时，三角形内部仍可能跨过一条细窄水道。航海专题需要针对水道约束三角化或进行精确裁切；仅增加几个顶点采样不能保证通道贯通。

### 5.5 小岛、极地与贴图

- 满足面积、范围、原始采样与大陆邻接等启发式筛选条件、且没有有效源高程采样的小岛，保留已有矢量轮廓，降低至 Y=0.045，并排除其起伏网格，避免借用邻近大陆高程产生虚假的尖峰。该筛选不能保证识别所有小岛，也不能补出源资料没有收录的岛屿。
- 高程范围之外返回 0，不向南北极外推。南极展示轮廓和近似平坦冰面，不含真实南极山地模型。
- 水平地表按经纬度生成 UV，纹理横向重复以适配新的切缝位置。
- 贴图加载成功后关闭重复的高程顶点染色；失败后使用高程分层颜色。当前两个纹理重试地址相同，并不是两个独立的资源源站。
- `dispose()` 负责释放地形几何体、材质和纹理；将来局部地形切换也必须遵守这一生命周期。

## 6. 海洋、水体与数据层

### 6.1 实景水面

海面使用 `three/examples/jsm/objects/Water.js`，几何体是 72×36 的平面，放置在 Y=0.015。法线贴图产生波光与扰动；当前反射目标尺寸为 1024×1024。

Water 表面覆盖整个沙盘，地表通过自身几何和深度遮挡露出海洋部分。水下使用厚度为 7.5 的海洋色长方体，侧面不透明；它表达沙盘体积，不是实测海深。

当前水纹主要是着色器视觉效果，不能直接据此计算船体起伏、真实海流速度或潮汐。

### 6.2 数据色层与特效遮罩

| 项目 | 当前实现 | 对航海专题的含义 |
| --- | --- | --- |
| 海温、气压、距平 | 1440×720 显示纹理，独立平面 Y=0.03 | 0.25° 是显示采样间隔，不是源资料精度 |
| 海岸覆盖 | 数据层延伸至陆地下面，由精细轮廓遮挡；部分邻岸缺测颜色做有限显示补边 | 不可把颜色覆盖结果用作船舶通航判定 |
| 缺测值 | 灰色斜纹；交互读数仍按原始格网返回缺测 | 不补造测量值 |
| 风推水、局部水面特效 | 360×180 的海陆遮罩 | 1° 遮罩不能准确限制窄海峡中的特效 |
| 温跃层剖面 | 前缘局部窗口中的 Shader 示意 | 不代表沙盘底部或航道真实水深 |

未来若给海峡增加尾迹、泡沫或局部海流，应使用局部水域面或局部高分辨率遮罩，不能沿用全球 1° 遮罩。

## 7. 为什么海峡、运河看不出缝隙

应逐项排查，不要一开始就把问题归因于贴图：

| 情况 | 判断方式 | 对应处理 |
| --- | --- | --- |
| 源轮廓没有通道 | 直接查看矢量两岸，水域已被合并或省略 | 换局部精细海岸线，补真实水域边界 |
| 底面开了，起伏面仍跨河 | 分别隐藏轮廓底面、起伏网格观察 | 两层共同裁切，约束三角形不得跨水道 |
| 有水道，全球视角不足一个像素 | 局部放大后通道恢复 | 提示位置、切近景，必要时使用带说明的显示夸张 |
| 海面被侧壁或旧模型挡住 | 检查封边、旧底面、旧起伏是否仍存在 | 成套替换该区域的几何，重建岸边侧壁 |
| 几何正确但纹理或特效越岸 | 关闭贴图与水面特效比较 | 对齐局部影像、海陆遮罩与坐标参考 |

Natural Earth 的 `1:110m` 和 `1:10m` 是地图比例尺系列，分别表示约 1:110,000,000 和 1:10,000,000，**不是 110 米或 10 米分辨率**。更细的 Natural Earth 可以改善区域轮廓，但不能因此承诺显示所有狭窄运河。[Natural Earth 物理地理资料](https://www.naturalearthdata.com/downloads/10m-physical-vectors/)

## 8. 航海专题建议采用的三层展示

以下均为后续方案，不是当前已完成的功能。

| 层级 | 教学用途 | 建议做法 |
| --- | --- | --- |
| 全球总览 | 出发地、目的地、跨洋航程及大洲关系 | 保留当前矩形沙盘，航线与船图标使用可读的屏幕尺寸 |
| 区域观察 | 接近大陆、绕过海角、寻找海峡入口 | 按区域加载更细的海岸、岛屿和高程，逐步拉近镜头 |
| 水道近景 | 展示船怎样通过狭窄、曲折的水道 | 加载经过核验的局部水域面、岸线与通行路线，采用局部坐标与适宜比例 |

初版建议使用独立的局部近景场景，并保持航程进度连续。全球场景保留入口标记；局部场景准备完成后切入，驶出后回到总览。这比立即把高精度地形无缝嵌入全球网格更容易验证。

若后续采用同场景分级细节（LOD），必须同时处理旧地形裁切、边界衔接、纹理对齐和显隐切换。相机拉近不是精度切换本身。

## 9. 精度应怎样补充

### 9.1 先解决海陆边界，再解决山体细节

推荐优先级：**水域连通关系 → 两岸轮廓 → 航线路径 → 地形高程 → 近景贴图与特效**。

| 数据 | 候选来源与用途 | 需要核查的边界 |
| --- | --- | --- |
| 区域陆地与岛屿 | Natural Earth 1:10m；用于区域级轮廓 | 仍为概化资料，不能直接当窄航道模型 |
| 更细海岸线 | GSHHG 或 OpenStreetMap 衍生陆地面，按区域裁切 | 检查版本、局部完整性和真实水道开口 |
| 人工运河及港湾水域 | 对应水域面、两岸线与有来源的航道资料 | 仅有中心线时不能自动认为知道真实宽度；海岸资料不保证包含人工运河 |
| 陆地高程 | 局部裁切 Copernicus GLO-30 / GLO-90 等资料 | 采样间隔不等于高程误差，也不能替代岸线或水下测深 |
| 历史航线 | 有来源的航行记录、历史地图与研究资料 | 不确定区段与现代地理底图必须区分 |

GSHHG 提供多档概化级别，可作为离线区域海岸资料的候选；具体水道是否足够准确仍须逐处检查。[GSHHG 项目说明](https://www.soest.hawaii.edu/wessel/gshhg/)

OpenStreetMap 衍生陆地面来自 `natural=coastline`，适合直接取得多边形；分块产品可能有重叠，局部处理需消除重复边。人工运河还应检查其独立水域要素。保存数据版本与署名信息，按数据源许可处理派生资源。[陆地面说明](https://osmdata.openstreetmap.de/data/land-polygons.html)、[OSM 许可说明](https://www.openstreetmap.org/copyright)

Copernicus GLO-30 / GLO-90 分别提供约 30 米、90 米采样的全球表面模型。它包含建筑和植被等表面影响，并不是纯裸地或海底模型；用于局部景观时需针对海岸、水面及资料缺口做处理。[Copernicus DEM 官方说明](https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM)

### 9.2 局部地形处理流程

1. 定义关键区域包围范围与外围缓冲区，记录经纬度坐标参考、数据日期、来源和许可。
2. 合并内部国家边界，清理重复点、自交与错误内环，保留岛屿、孔洞和关键窄水道。
3. 在适合该区域的米制投影或局部坐标下处理几何；不要直接把“0.001°”当成固定米数的航道宽度。
4. 将海峡或运河水域从陆地面中扣除。开放水道须接通两侧海域，不能错误处理成封闭内湖。
5. 对陆地区域做带边界约束的三角化或精确裁切，保证三角形的内部也不跨水道。再采样局部高程，重建岸边侧壁。
6. 同步生成局部水面范围、特效遮罩与通行判定边界，统一数据源与坐标变换。
7. 同场景替换时移除覆盖区域的旧轮廓底面、旧侧壁和旧起伏；独立近景则使用完整局部模型。沿海边界不使用会重新封住通道的任意裙边。
8. 在入口、出口、最窄处、急弯和岛屿间通道检查几何连通性，再检查光照、贴图和低视角表现。

精度需要与水道宽度、相机距离共同决定。若局部遮罩采用栅格方式，应让最窄的目标水道横跨多个像素；若做不到，应进一步加密或直接依赖矢量水域几何，避免以一次中心采样决定整块海陆。

### 9.3 麦哲伦海峡与苏伊士运河分别处理

**麦哲伦海峡**：优先核验两岸及岛屿轮廓，保证曲折水道连续；局部山体与岸坡用于帮助理解通行环境。船的路线应在正确的海峡水域内通过，不能因曲线平滑从岸角穿过去。

**苏伊士运河**：建立独立的人工水道面及两岸地形，并根据教学年代控制是否存在、如何连通。不要仅在陆地贴图上画一条蓝线后让船穿过仍完整的陆地网格。

现代苏伊士运河于 **1869 年 11 月 17 日**正式通航。地理大发现时期的航行演示不能把这条现代通道设为捷径；可在另一个阶段比较运河开通前后的航线。[苏伊士运河管理局历史说明](https://www.suezcanal.gov.eg/English/About/SuezCanal/Pages/CanalHistory.aspx)

现代高精度地图也不自动等于历史海岸复原。无法确认历史岸线、港口或具体航迹的部分，应注明采用现代地理底图或示意重建。

## 10. 航线、船只和距离

### 10.1 地理路径与显示路径分开

- 地理路径保存经纬度、途经点、日期、来源和不确定区段。
- 显示路径负责投影、分段、曲线采样、尾迹与相机跟随。
- 需要平滑时，校验平滑后的整段路径，而不只是控制点；Catmull-Rom 等曲线可能在转弯处偏出原路线。
- 通道内优先沿经核验的路线行驶，并检查路径与陆地的相交以及船体所需净宽；“路线中心点在水里”不足以保证船体不碰岸。
- 跨 30°W 沙盘切缝时拆成两侧显示段，保留同一条逻辑航程。船可通过镜头转场或两侧同步标记衔接，不能横穿沙盘补连接。

航程数值应来自地理路径逐段的测地距离累加。动画速度和全局船图标大小可为教学做调整，不能把显示夸张后的长度、船宽当作真实数值。

当前洋流已有可参考的跨缝显示机制：先解包路径 X 坐标，再将连续路径复制到 X 偏移 -72、0、+72 的位置，并裁切到沙盘范围。可以复用这种坐标处理思路，但不能直接把洋流样条当作通航路径；洋流代码没有执行船舶避陆、宽度或水深校验。

### 10.2 全球可读性与近景真实感

全球视角的船使用可读的图标尺寸；进入水道后切换为适合局部尺度的船模型，避免一个全球夸大的船体比海峡还宽。

优先通过镜头和局部放大解决通道太细。确实需要加宽显示时：

- 保留原始坐标与真实几何作为计算依据，单独生成展示几何。
- 标注“局部放大”或“宽度夸张示意”。
- 调整后的岸线、水面、船与路线必须使用一致的显示变换。
- 不改变海陆连通关系，不从夸张后的画面读取实际距离。

## 11. 教学步骤与性能

一次关键水道的讲解建议拆为：

```text
全球交代目标与已走航程
  → 接近入口，提示为何寻找这条水道
  → 局部近景，辨认两岸、岛屿与通行方向
  → 跟随船只穿越，按需要暂停解释
  → 驶出水道，回到全球观察新的海域与航程
```

继续复用现有按步骤声明效果、手动切步、暂停和镜头跟随的思路。船位、日期、尾迹、转场和步骤进度使用统一的演示时钟；暂停时共同停止，切换详细模型不应重置已走航程。

性能上建议：

- 局部资源离线裁切、简化并验证后发布 OSS，浏览器按需加载；清单记录 bounds、级别、版本、来源、许可与校验值。
- 全球与区域层使用概化几何，进入讲解前预取下一个关键区域；局部准备完成才切换，加载失败保留总览和重试入口。
- 分级切换使用不同的进入/退出阈值，避免镜头在阈值附近来回切换；撤销过期加载，防止用户切步后旧请求覆盖新场景。
- 同场景内尽量复用一个主水面；增加官方 Water 实例可能增加反射渲染成本。独立近景仅保留必要的水体实例。
- 保持坐标、海平面与纹理方向一致，处理接边裂缝和共面闪烁；区域坐标平移或独立场景可减少近景大数值精度问题。
- 卸载局部资源时释放 GPU 资源，并在目标课堂设备实测帧率、首次加载时间和连续切换后的内存占用。

将全球起伏格网从 1° 改成 0.1°，节点规模大致增加到原来的 100 倍，却仍无法恢复源轮廓省略的水道。因此应优先局部加密，而不是首先将整个世界全部加密。

## 12. 建议实施顺序与验收

### 12.1 分阶段实施

1. **沙盘底座复用**：梳理 `world.ts`、水体、背景、坐标变换与生命周期，抽出与气候教学无关的接口；保留现有海气页面行为。
2. **一个海峡试点**：以麦哲伦海峡为局部精度试点，先完成岸线、水道连通性和船舶路径，再接镜头与课文。
3. **全球与局部衔接**：实现航程状态共享、区域预加载、转场、暂停和手动跳步。
4. **历史扩展**：添加航海家分段航线、资料来源和年代控制；现代运河放在符合年代的专题或前后对比中。
5. **多区域复用**：再决定是否把独立近景升级为同场景 LOD，并扩展其他海峡和港湾。

建议未来按“基础沙盘 / 区域资源 / 航程状态 / 船舶表现 / 教学步骤”分离职责。当前这些模块还没有抽成公共组件，本文不把建议目录当作已有代码。

### 12.2 验收清单

- [ ] 每个精细区域有来源、日期、坐标参考和明确精度说明。
- [ ] 入口、出口、最窄处与急弯保持水域连续；旧底面、起伏和侧壁没有封住水道。
- [ ] 路线与船体均不穿岸、不越岛；平滑处理后重新校验。
- [ ] 跨沙盘切缝的航线无拉伸长线，船位和航程连续。
- [ ] 水面、局部特效和岸线使用一致的水域边界，没有尾迹穿陆。
- [ ] 全球、区域、近景之间切换无明显裂缝、闪烁和贴图错位。
- [ ] 暂停后船、日期、尾迹与步骤进度冻结；恢复后连续播放。
- [ ] 旧年代没有出现尚未开通的现代运河；不确定航迹有明确说明。
- [ ] 视觉夸张与真实数值分开，局部高程插值没有被表述为新增观测精度。
- [ ] 在常用窗口尺寸和课堂设备上检查可读性、帧率、加载失败和重复切换后的内存。

当前可复用的是全球沙盘的渲染基础。航海专题最优先增加的是 **可靠的局部水域边界与贯通几何**，随后才是更细的山体和更丰富的船舶效果。
